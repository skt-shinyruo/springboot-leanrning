# 章节逐章补强建议（part-00-guide 指南）

### 第 28 章：03. 主线时间线（mainline timeline）

- 建议把“时间线”覆盖到两个维度：容器生命周期（refresh 主线）+ AOP 关键插入点（何时决定是否代理、何时创建代理、何时进入拦截链）。
- 增补“关键类与关键点”清单：把时间线上的关键节点落到 Spring 具体类/方法（例如 AutoProxyCreator、ProxyFactory、MethodInvocation），并给出为什么是关键点。
- 增补 1 张可复用的序列图（建议 Mermaid）：用“Bean 创建 → 后置处理 → wrapIfNecessary → proxy invoke”串起来，后续章节引用这张图即可。
- 增补“最小验证闭环”：选一个最短的 Lab/Test 路径，让读者能在 5 分钟内看到“代理创建 + 代理调用”的两个关键瞬间。

### 第 29 章：00. 深挖指南（deep dive guide）

- 强化“怎么读”而不是“读什么”：建议明确每个 Part 的目标、依赖前置、以及首次进入时的推荐路径（先快后深）。
- 增补“实验与章节映射”：把每个核心 Lab/Test 映射到“它验证/解释的章节”，减少读者在 docs 与代码之间来回跳转成本。
- 增补“Debug 约定”：统一说明断点策略（哪些断点是“噪声大”的，如何用条件断点/过滤减少干扰）。
- 增补“学习闭环模板”：一个轻量模板即可（现象 → 断点/日志 → 源码 → 结论 → 可复现），后续章节复用该模板而不强制统一格式。

### 第 29 章：01. AOP 调用链（aop invocation call chain）

- 建议补强“从代理入口到目标方法”的完整链路：明确 JDK 代理与 CGLIB 代理在入口上的差异，以及它们如何汇聚到同一套拦截链执行模型（`MethodInvocation.proceed()`）。
- 增补“拦截链的对象图”：把 Advisor/Interceptor/Invocation 三者关系画清楚，并解释链是“创建时组装”还是“调用时计算/缓存”。
- 增补“proceed 嵌套”的直觉解释：用一个最小例子解释为什么会出现 proceed 递归/嵌套（多层 around advice），并给出如何在调试器中观察层级。
- 给出一个可复现的 Lab/Test 入口：要求能稳定观察到 `MethodInvocation` 的推进过程与链路顺序。

### 第 29 章：02. 断点地图（breakpoint map）

- 建议按“目的”分类断点：创建代理类/决定是否代理/构建 Advisors/进入 invoke/proceed/执行目标方法等，避免一股脑列断点。
- 增补“降噪策略”：例如条件断点、按 beanName 过滤、按方法名过滤，以及哪些类会被频繁命中（避免读者第一次调试就被淹没）。
- 给出“最小断点集合”：只靠最少断点也能串起一次主线；同时再给“进阶断点集合”覆盖分支。
- 与分支矩阵联动：断点地图要能支撑“为什么没被代理 / 为什么走了 JDK 代理 / 为什么多层代理”等典型问题定位。

### 第 29 章：分支决策矩阵（branch decision matrix）

- 建议从“问题驱动”补强：以常见问题为行（不生效/代理类型错误/Advice 没进来/多层代理/顺序不对），以“定位步骤”作为列（现象→验证→断点→结论）。
- 增补 AutoProxyCreator 分支：例如哪些类会被认为是 infrastructure 而跳过、哪些 Advisor 会被筛掉、何时会返回原 bean。
- 增补多代理分支：解释“同一个代理里有多个 Advisor”与“多个代理层层包裹”的区别，以及如何确认属于哪一种。
- 与 Appendix（common pitfalls）互相引用：矩阵给“定位路径”，pitfalls 给“典型坑与修复”，避免两边重复但不打通。

## 1. 需求

### 背景
本仓库已经具备“模块边界 + 可运行实验入口（Labs / Exercises）+ 模块 docs 主线”的文档体系，但要做到“像计算机教材”仍有三个痛点：

- **入口不够稳定**：读者从模块根 `README.md` 或模块 `docs/README.md` 进入时，经常不知道“先跑哪个入口建立证据链”，也不清楚读完的退出条件。
- **复盘出口不够干净**：部分模块的自检页混入排坑内容或跨模块导航，导致“复盘 → 验证 → 回到主线”的闭环不稳定。
- **路径口径漂移**：少量模块根 `README.md` 对 `docs/**.md` 的引用使用了过时命名或不可点击的路径，影响顺读与维护。

用户要求：对全项目做“教材化加厚”，文风要像计算机书籍（克制、结构化、可操作、可验证），避免“AI腔/口水话”。

### 目标
- **全模块覆盖（v1 基线）**：`spring-boot-modules/*` 与 `spring-core-modules/*` 的“入口层”达到一致的“先跑后读”闭环标准。
- **书籍化体验**：读者从任一模块入口进来，都能在 5 分钟内跑通一个稳定入口（Book/Branch Matrix），并在 30 分钟内完成一次“实验 → 解释 → 自检”的闭环。
- **深度落点（练习册化）**：把自检页写成“可验证复盘”，每个问题都能指向证据链入口（测试/断点/关键类）。
- **构建不回退**：保持 `docs/SUMMARY.md` 为站点导航 SSOT，不做结构级重排；`mkdocs build` 可通过。

### 约束条件
```yaml
时间约束: 本轮以“入口闭环达标 + 自检页加厚”为主；机制正文的深挖扩写分批迭代
性能约束: 不引入重型构建步骤；mkdocs 构建时间不显著增加
兼容性约束: 不破坏现有目录结构；不重排 `docs/SUMMARY.md` 的既有模块导航（必要时仅新增入口）
业务约束: 所有 `README.md` 必须中文；book 主线只做聚合与指引，不复制模块正文
```

### 验收标准
- [ ] 每个模块根 `README.md` 都提供 “Start Here（可跑入口）”：至少包含 Book Matrix + Branch Matrix 两条命令（统一格式：`mvn -q -pl :<artifactId> -Dtest=<TestClass> test`）
- [ ] 每个模块根 `README.md` 的“推荐 docs 阅读顺序”使用可点击相对链接，且指向存在的 `docs/**.md`
- [ ] 每个模块 `docs/appendix/02-self-check.md` 为纯自检页：不重复常见坑正文；包含 Book/Branch Matrix 入口 + 断点/分支矩阵跳转 + 退出条件
- [ ] 在 `docs-site/` 执行 `mkdocs build -f mkdocs.yml -d /tmp/site-springboot-learning` 构建通过
- [ ] 抽查 3 个模块闭环：`docs/book/README.md` → 模块 `docs/README.md` → 运行 Book Matrix → 自检页复盘，链路不断

## 2. 方案

### 技术方案
采用“入口层统一 + 复盘出口加厚”的教材化策略，不做全量正文推倒重写：

1. **模块根 README（GitHub 入口）教材化**：统一补齐 Start Here（Book/Branch Matrix）+ 可点击 docs 阅读顺序 + 排坑/自检出口 + 下一步跨模块推荐。
2. **模块自检页重写（复盘出口）**：按统一模板重排 `docs/appendix/02-self-check.md`，保证问题可验证、入口可运行、出口可回到主线。
3. **常见坑页按需对齐**：仅在“坑页/自检页边界混乱或入口缺失”时补齐最短证据链入口，不做大篇幅扩写（避免重复正文）。
4. **构建自检**：以 mkdocs build 为硬门槛；对入口页做相对链接抽查，避免“像书但断链”。

### 影响范围
```yaml
涉及模块:
  - spring-boot-modules/*: 模块根 README + 模块 docs 自检页（必要时 common pitfalls 轻量调整）
  - spring-core-modules/*: 模块根 README + 模块 docs 自检页（必要时 common pitfalls 轻量调整）
  - docs-site/: 构建自检（不改大结构）
预计变更文件: 60-120（以 README + self-check 为主；少量补充 common pitfalls 与入口链接修复）
```

### 风险评估
| 风险 | 等级 | 应对 |
|------|------|------|
| 范围膨胀导致写作质量下降 | 中 | 先保证“入口闭环达标”，自检页按模板统一；机制正文仅做必要修补 |
| 相对链接断链（跨目录引用） | 中 | 以模块内相对链接为主；集中对 README 与 appendix 做抽查 |
| 文风不一致（教材 vs 笔记/口语） | 中 | 在入口层与自检页强制统一模板；正文保留原风格，后续分批统一 |
| 站点构建 warnings 噪声较多 | 低 | 以“构建通过”为硬门槛；warnings 作为后续整洁度迭代处理 |

## 4. 核心场景

> 执行完成后同步到对应模块文档

### 场景: 从模块根 README 建立证据链
**模块**: 任意模块（全覆盖）
**条件**: 读者只打开模块根 `README.md`
**行为**:
- 按 “Start Here” 运行 Book Matrix（主线）或 Branch Matrix（排障）
- 跳转模块 `docs/README.md` 与 `docs/appendix/02-self-check.md` 完成复盘
**结果**: 读者能在 30 分钟内形成“现象→解释→自检”的闭环，不依赖外部博客

### 场景: 在自检页完成一次“可验证复盘”
**模块**: 任意模块（全覆盖）
**条件**: 已能运行对应模块测试
**行为**:
- 运行 Branch Matrix
- 对照断点地图/分支矩阵回答自检问题
**结果**: 每个自检问题都能指向可运行入口或可下断点的证据点

## 5. 技术决策

> 本方案涉及的技术决策，归档后成为决策的唯一完整记录

### docs-textbook-style-modules-deepen#D001: 全模块“先入口后正文”的教材化策略
**日期**: 2026-02-25
**状态**: ✅采纳
**背景**: 全模块直接扩写机制正文会导致改动面失控与维护成本爆炸；而读者最缺的是“如何读/如何验证/如何复盘”的教材式闭环。
**选项分析**:
| 选项 | 优点 | 缺点 |
|------|------|------|
| A: 全量重写所有机制正文（深度优先） | 理论深度上限高 | 范围极易失控；写作质量波动大；易与既有正文重复/漂移 |
| B: 入口闭环达标 + 自检/排坑加厚（推荐） | 全模块可落地；读者立刻受益；后续可渐进加深正文 | 单次迭代对正文深度提升有限，需要后续分批扩写 |
**决策**: 选择方案 B
**理由**: 先把“读法与证据链”做成统一基建，再把深度写作投入到最有复用价值的模块与章节
**影响**: 覆盖全部模块入口层（根 README + docs appendix）；正文页仅做必要修补

## 1. 需求

### 背景
当前项目文档更偏“模块/零散主题”组织，读者需要自行拼接学习路径：知道要看什么、按什么顺序看、每一步该做什么实验与练习的成本较高。与此同时，根 `README.md` 与文档站点说明（`docs-site/README.md`）缺少“总目录 + 学习主线”的入口形态，不利于把项目作为系统化学习材料使用。

本提案希望在不破坏现有 `*/docs/` 模块文档结构的前提下，新增一条“全书主线”的聚合层（类似计算机教材的章节组织），让读者能够按章节推进学习，同时通过大量链接跳转到既有模块文档、测试与实验入口，避免重复撰写/复制模块正文。

### 目标
- 把项目文档组织成“更丰富、更像计算机教材”的形态：根 `README.md` 作为入口与总目录。
- 在 `docs/` 下新增 `docs/book/` 作为“全书主线”聚合层，提供不少于 10 章的主线章节正文（只聚合与指引，不复制模块正文）。
- `docs/SUMMARY.md` 继续作为 MkDocs literate-nav 的单一事实来源（SSOT），并新增“全书主线”分组挂载这些章节。
- 更新 `docs-site/README.md` 与根 `README.md` 的说明，匹配新结构与阅读路径。

### 约束条件
```yaml
时间约束: 无硬性截止（建议分阶段提交：先骨架，再补链接与练习）
性能约束: 不引入额外构建步骤；文档体量增长可控（章节以“链接聚合”为主）
兼容性约束:
  - 不破坏现有模块文档（*/docs/）结构与既有导航
  - docs/SUMMARY.md 继续作为 MkDocs literate-nav 的 SSOT
业务约束:
  - 不引入新 MkDocs 插件
  - 不改变 docs-site/mkdocs.yml
```

### 验收标准
- [ ] 新增目录 `docs/book/`，包含不少于 10 个主线章节 Markdown 文件（建议按序号命名，如 `docs/book/01-*.md`）。
- [ ] 每个主线章节遵循统一模板，至少包含：学习目标 / 概念框架 / 实验入口 / 常见误区 / 练习 / 小结 / 延伸阅读，并以链接为主指向现有模块文档与实验/测试入口（避免大段复制模块正文）。
- [ ] `docs/SUMMARY.md` 新增“全书主线”分组并挂载全部主线章节；原有导航结构保持不变（仅新增，不重排、不删除）。
- [ ] `docs-site/mkdocs.yml` 未被修改，且使用现有配置可完成 `mkdocs build`（或等价构建）通过。
- [ ] 根 `README.md` 更新为入口与总目录：包含“如何阅读/学习路径”与文档入口，链接到 `docs/SUMMARY.md` 与主线章节。
- [ ] `docs-site/README.md` 更新为文档站点说明：明确 `docs/SUMMARY.md` 为导航 SSOT，并说明“全书主线”的位置与维护方式。

## 2. 方案

### 技术方案
本方案以“聚合层主线章节 + 既有模块文档”组合实现，核心由四部分组成：信息架构、写作规范、章节模板、导航挂载方式。

#### 2.1 信息架构（Information Architecture）
- 现有：各模块在各自的 `*/docs/` 下维护细节内容（保持不变）。
- 新增：`docs/book/` 作为“全书主线”聚合层，仅提供章节主线叙事与学习引导。
- `docs/SUMMARY.md` 仍是 MkDocs literate-nav 的 SSOT，在其中新增分组挂载 `docs/book/` 章节。

建议目录结构（示意）：
```text
docs/
  SUMMARY.md                 # SSOT（literate-nav）
  book/
    README.md                # 全书主线总览/阅读建议
    01-getting-started.md
    02-java-basics.md
    03-spring-boot-basics.md
    ...
```

#### 2.2 写作规范（Writing Guide）
- **章节定位**：主线章节只做“目标/框架/入口/误区/练习/小结/延伸阅读”，不复制模块正文；正文以链接与清单为主。
- **链接优先**：优先链接到现有 `*/docs/`、示例工程说明、以及测试/实验入口（如 `*/src/test/**`、`*/README.md` 等）。
- **可维护性**：每章控制在“可快速浏览”的篇幅；当模块文档更新时，主线章节只需调整链接与引导语。
- **一致性**：章节命名使用序号前缀；统一标题层级与小节顺序；链接使用相对路径（仓库内可点击）。

#### 2.3 章节模板（Chapter Template）
每章建议采用固定结构（可作为 `docs/book/_template.md` 的内容来源）：
```markdown
# 第 X 章：{章节标题}

## 学习目标

## 概念框架

## 实验入口

## 常见误区

## 练习

## 小结

## 延伸阅读
```

#### 2.4 导航挂载方式（Navigation Mounting）
- 在 `docs/SUMMARY.md` 中新增分组：`全书主线`。
- 在该分组下按章节顺序挂载 `docs/book/*.md`。
- 保持既有分组与路径不变，不做“全站重构式”迁移。

### 影响范围
```yaml
涉及模块:
  - 根目录文档: README.md（入口与总目录）
  - 文档导航: docs/SUMMARY.md（literate-nav SSOT，新增“全书主线”分组）
  - 文档站点说明: docs-site/README.md（与新结构对齐）
  - 主线聚合层: docs/book/*.md（新增 10~14 章为主，含总览页）
  - 现有模块文档: */docs/（不改结构，仅被链接引用）
预计变更文件: 13~18（以新增 docs/book/ 章节为主）
```

### 风险评估
| 风险 | 等级 | 应对 |
|------|------|------|
| 主线章节链接失效（路径变更/相对链接写错） | 中 | 统一链接规则；在验收时运行 `mkdocs build` 并抽查关键链接；优先链接到稳定入口（SUMMARY、模块 README）。 |
| 文档导航变复杂，读者不知道从哪开始 | 中 | 根 `README.md` 明确“推荐阅读路径”；`docs/book/README.md` 作为主线总览与索引。 |
| 章节内容膨胀，演变成复制模块正文，维护成本上升 | 高 | 写作规范强约束：章节只做聚合与指引；把“细节解释”留在模块文档；章节控制篇幅。 |
| 不改插件/配置导致某些期望的导航效果做不到 | 低 | 以 `docs/SUMMARY.md` 的 literate-nav 能力为边界；通过章节内链接与清单补足表现。 |

## 4. 核心场景

> 执行完成后同步到对应模块文档

### 场景: 初次进入项目（从 README 找到学习路线）
**模块**: 文档入口（README + SUMMARY）
**条件**: 读者第一次打开仓库根 `README.md`
**行为**: 按 README 的“推荐阅读路径”进入 `docs/SUMMARY.md` 或 `docs/book/README.md`，选择章节并跳转到对应模块文档
**结果**: 读者能在 1～2 次点击内到达主线章节与关键模块文档入口，不需要在仓库内盲目搜索

### 场景: 按章实践（从章节进入实验/测试入口）
**模块**: `docs/book/` 主线章节
**条件**: 读者正在阅读某一章
**行为**: 通过“实验入口/练习/延伸阅读”链接跳转到对应模块文档、示例工程说明与测试入口，按指引运行或验证
**结果**: 读者可以复现实验并完成练习，主线章节保持轻量、可维护（以链接聚合为主）

## 5. 技术决策

> 本方案涉及的技术决策，归档后成为决策的唯一完整记录

### docs-book-textbook-style#D001: 主线聚合层（docs/book）vs 全站重构式教材化
**日期**: 2026-02-25
**状态**: ✅采纳
**背景**: 需要把文档做成“像教材的主线章节”，但同时必须不破坏现有 `*/docs/` 结构、保持 `docs/SUMMARY.md` 为 SSOT，且不引入新插件、不改 `docs-site/mkdocs.yml`。因此需要在“增量聚合”与“整体重构”之间做出取舍。
**选项分析**:
| 选项 | 优点 | 缺点 |
|------|------|------|
| A: 新增 `docs/book/` 作为主线聚合层（章节以链接聚合为主） | 变更小、风险低；不破坏现有模块文档；可逐步完善；符合“不改插件/配置”的约束 | 初期章节信息密度可能偏“索引型”；需要持续维护链接准确性 |
| B: 全站重构为教材式目录（迁移/重排现有模块文档） | 导航更“统一”；章节与模块更一体化 | 破坏面大；易引入大量断链；需要更强的配置/插件能力；与“不破坏模块文档结构”冲突 |
**决策**: 选择方案 A
**理由**: 方案 A 以新增聚合层实现“教材主线”，对现有结构干扰最小，能在不改变 MkDocs 配置与插件的前提下快速落地，并允许后续按章节逐步增强内容与练习。
**影响**:
  - 新增 `docs/book/` 与主线章节文件
  - 更新 `docs/SUMMARY.md`（新增分组挂载）
  - 更新根 `README.md` 与 `docs-site/README.md`

# 文档写作规范（教材式 / 中性口吻）

本页面向仓库维护者与贡献者，用于把文档从“模板化清单/口号式结论”迁移为更接近**教材/书稿**的连续叙述，同时保留本仓库最重要的特性：**可运行、可验证、可回归**。

> 约定：本仓库所有 `README.md` 使用中文撰写。

---

## 1. 总体目标（读者体验）

读者打开任意一页时，应当能在 30 秒内回答三个问题：

1. 这页在解决什么问题（或解释什么现象）？
2. 这页给的“事实入口”是什么（测试/命令/观察点）？
3. 读完后下一步去哪里（同模块下一章 / 另一模块的最短跳转）？

如果这三点成立，文档就更接近“书”而不是“索引”。

---

## 2. 文风：中性教材口吻（不聊天、不元叙事）

### 2.1 推荐写法

- 用“本章/本节/读者/可以观察到/因此/这意味着”推进逻辑。
- 用“现象 → 解释 → 验证”组织段落（每个结论都能落到可验证的入口）。
- 允许有判断，但判断要能被实验、断言、断点观察点支撑。

### 2.2 避免写法（常见 AI 味来源）

- “先把结论放前面……”
- “建议/推荐/强烈建议……（但不给验证手段）”
- “本文将介绍/本文会讨论……（空泛铺垫）”
- “只堆列表，不讲为什么、也不讲如何验证”

### 2.3 句式替换（可直接套用）

| 不推荐 | 更像教材的替换 |
| --- | --- |
| 先把结论放前面：X | 这一节要回答一个问题：为什么会出现 X？ |
| 推荐先做 A 再做 B | A 与 B 的先后来自一个事实：……（给出实验入口/观察点） |
| 常见误区：…（列表） | 误区的典型表现是……；原因通常是……；用……可以验证。 |

---

## 3. 结构：像书一样推进（段落为主，列表为辅）

### 3.1 正文页（`part-xx/*.md`）推荐骨架

> 不是每章都必须完全一致，但尽量让读者形成“读法惯性”。

1. **问题**：开篇 1–2 段点名困惑/现象（不要先抛一堆标题）。
2. **实验**：给出最短可跑入口（mvn 命令 + 测试类链接），写清楚“期望观察到什么”。
3. **解释**：机制主线用段落推进；必要时插入小表/小列表做归纳。
4. **边界**：反例/误区写成“现象→原因→验证”。
5. **小结**：≤ 3 条可复述句（每条都能回指到实验或观察点）。
6. **延伸阅读**：少量链接，并写一句“为何读它”。

#### 实验块写法示例

```markdown
## 实验：把“最终值在哪里”跑成事实

运行：

- `mvn -q -pl :spring-boot-basics -Dtest=BootBasicsOverrideLabTest test`

观察：

- `Environment#getActiveProfiles()` 的返回值
- `Environment#getProperty("app.greeting")` 的最终值

读者应能回答：

- 同名 key 冲突时，最终值来自哪个来源？
```

### 3.2 目录页（模块根 `README.md`）推荐骨架

目录页的职责不是“列链接”，而是“给路线”。推荐结构：

- **导论**：本模块边界是什么、读完能获得什么能力。
- **10 分钟入口**：一个最短闭环（命令 + 预期现象）。
- **按路线阅读**：主线 → internals → appendix（用段落解释顺序原因）。
- **按问题查索引**（可选）：把高频现象映射到章节/断点/实验入口。

### 3.3 少用“模板化章节标题”

如果章节标题高度同质（比如“学习目标/概念框架/常见误区/练习”在每页机械出现），读感会更像“规范文档”。可以保留这些维度，但建议：

- 把“学习目标”写进自然段的第一段，而不是作为固定栏目。
- 把“常见误区”写进边界讨论里，而不是独立堆列表。
- 把“练习”写成实验延伸（“把断言改成……并观察……”）。

---

## 4. 证据链：结论必须可回归

本仓库的文档不是“知识总结”，而是“把结论绑定到证据入口”：

- 命令：尽量给出可复制的 `mvn -q -pl :<module> -Dtest=<TestClass> test`
- 测试类：给出源码相对链接（便于跳转阅读）

调试时建议重点盯：至少给出 1–3 个关键方法/变量（断点/Watch List）


当结论与代码行为冲突时，以代码与测试为准。

---

## 5. 链接与导航（避免维护成本失控）

- 站点侧边栏的 SSOT 是 `docs/SUMMARY.md`。
- `docs/SUMMARY.md` 只维护全站的“模块入口/全书主线/附录”等高层导航；**不再逐条列出各模块 `docs/*.md`**。
- 模块内章节的阅读顺序（SSOT）在各模块根 `README.md` 的“目录（唯一顺序来源）”维护；新增/移动/重命名模块内 `docs/*.md` 时，优先更新该模块 `README.md`。
- 链接优先使用**相对路径**，避免把 URL 写死在多处。

> 现有注释块（例如 `<!-- CHAPTER-CARD:START -->`、`<!-- GLOBAL-BOOK-NAV:START -->`、`<!-- BOOKIFY:START -->`）当前不影响 MkDocs 渲染；为降低迁移风险，默认保留，但允许调整其内容。

# 章节逐章补强建议（docs 根目录）

### spring-core-aop 文档导航（Docs TOC）

- TOC 结构建议按“学习路径”组织：Guide（主线资产）→ Fundamentals（基础机制）→ AutoProxy/Pointcuts（创建与匹配）→ Stacking（复杂场景）→ Appendix（坑位与自测）。
- 去重与分组：当前 TOC 中存在重复链接的迹象；建议整理为“唯一入口 + 章节列表 + 复用链接”（例如：断点地图与分支矩阵只在 Guide 列一次，正文引用即可）。
- 增补“快速闭环入口”：在 TOC 顶部给出 1～3 条最小闭环路径（例如：跑一个 Lab → 下断点 → 看一次拦截链 → 回到章节解释），降低首次进入成本。
- 增补“缺失主题的入口”：若模块中存在测试但 docs 未覆盖（例如并发/性能），建议在 TOC 中显式补齐章节占位并链接到对应 Lab。
- 强化“章节与验证映射”：每个章节链接旁边建议注明对应 `-Dtest=...` 的 Lab/Test 名称，读者无需全文搜索即可找到验证入口。

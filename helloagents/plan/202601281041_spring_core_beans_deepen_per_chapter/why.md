# why：spring-core-beans 全章“逐章深挖”深化计划

## 背景与动机

你要的不是“把某几章补齐”或“套一个统一模板”，而是把 `spring-core-modules/spring-core-beans` 当成一套可长期演进的**源码进阶 + 面试复述 + 团队内训**教材：

- 阅读者能从**每一章**得到“更深入一层”的内容：不仅知道结论，还能解释原因与边界。
- 章节之间形成“主线 + 分支”的连续体验：同一概念在不同章节出现时能被更深地复用，而不是重复讲。  
  但不通过新增“桥接小节”来解决，而是通过内容深挖与术语/锚点一致性来实现。
- 能服务三类目标人群（你已明确）：
  - 源码进阶：更关心“算法/数据结构/分支条件/调用链”
  - 面试：更关心“标准答案 + 追问 + 反例”
  - 团队培训：更关心“可跑的闭环 + 可授课的叙事”

## 现状判断（基于当前 docs 70 章）

当前文档已经具备“教程化框架”（导读/主线/排障/面试/断点/Lab 入口/导航），但要做到你说的“深度完善”，还需要进一步做到：

- **把每章的“核心机制”讲到可复述的深度**：不仅能指出关键方法名，还能说明“为什么这个分支会走到这里/这个变量为什么决定结果”。
- **把每章的“边界”讲成可推导的结论**：把常见误归因逐条对照到源码分支（而不是堆坑点）。
- **把每章的“真实世界”补齐**：包括与 Boot、AOP、Tx、Environment、AOT 的交叉点；以及常见“线上症状 → 证据链 → 修复”。

## 本方案交付物（Solution Design 阶段）

本次生成的是一个“可长期迭代的方案包”，交付物为：

- `how.md`：整体深化策略（怎么逐章推进、怎么分批落地、怎么避免返工）
- `task.md`：逐章的“具体补充/完善/深入策略”（每章都有，不套固定标准，按章定制）

## 范围与非范围

**范围：**

- `spring-core-modules/spring-core-beans/docs` 的全部 70 个章节：逐章给出深化策略，并形成可执行任务清单。
- 允许在后续实施阶段按章节需要新增/调整对应 Lab/Test（不强制每章都有新增代码，但允许“章 → 实验”一起演进）。

**非范围（本方案不在本轮直接做）：**

- 立刻重构整套目录结构（路径保持稳定，避免链接与读者路径被打断）
- 立刻对 Spring Framework 源码做镜像式逐行注释（以“机制域 + 证据链”优先）

## 风险与应对

- 范围过大导致“写成百科”：应对策略是**分批迭代**，每批只深化一组章节，并在每批末尾做一次“互链/一致性回归”。
- 内容深化与可运行闭环之间的投入失衡：应对策略是允许“纯文档深化”与“补实验”两条路线并行，但每次合并都要保留可验证入口（至少能复现关键现象或断言）。

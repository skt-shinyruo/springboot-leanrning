# 章节逐章补强建议（part-01-proxy-fundamentals 代理基础）

### 第 30 章：01. AOP Proxy 心智模型（aop proxy mental model）

- 建议把“代理是什么”拆成两段：代理创建（谁决定/何时创建）与代理调用（谁拦截/如何执行链），读者更容易建立因果链。
- 增补核心对象图：`AdvisedSupport` 如何持有 `Advisor` 列表，`Advisor` 如何适配成 `MethodInterceptor`，以及 `TargetSource`/target 的关系。
- 增补“缓存与复用”的解释：哪些东西会缓存（例如方法匹配/拦截器链），哪些是每次调用新建（例如 invocation），用来解释性能与并发章节的基础。
- 给出一个最小验证入口：跑一个最简单的代理示例并在调试器里观察对象图（Proxy/Advised/Target）。

### 第 31 章：02. JDK vs CGLIB（jdk vs cglib）

- 建议补强“选择逻辑”与“可观测性”：不仅解释差异，还要说明如何在运行时确认当前走的是哪条路（以及为什么）。
- 补强“限制与边界”：接口代理与类代理分别能拦截什么（final/private/static 等），并用可复现方式证明，而不是仅口头描述。
- 补强“如何影响选择”：例如 `proxyTargetClass`/相关配置项的作用边界与副作用（包含对调试与排障的影响）。
- 给出一个对照 Lab：同一业务方法在两种代理策略下的类名、类型检查、可拦截性差异。

### 第 32 章：03. 自调用（self invocation）

- 建议用“为什么失效”的最小心智模型解释：代理只拦截“经过代理对象的调用”，而类内部 `this` 调用绕过代理。
- 补强解决方案对比：拆分 bean / 自注入 / `AopContext`（exposeProxy）/ 织入（weaving）等路径，分别给出适用场景与代价。
- 补强“常见误区”：例如事务/缓存等注解在自调用场景下失效的现象如何验证、如何定位。
- 给出一个最小实验：让读者能亲眼看到“外部调用生效、内部调用失效”的对比，并能用断点验证调用路径。

### 第 33 章：04. final 与代理限制（final and proxy limits）

- 建议系统化列出“不可拦截”的类别，并强调不同代理机制的差异（接口代理 vs 类代理）。
- 补强易漏边界：final class/final method/private method/static method/构造器等的行为与误解点（以“能否进入拦截链”为判据）。
- 补强“修复策略”：给出工程上更常用的解决方式（接口抽象/拆分/避免 final/使用织入等）及其取舍。
- 给出一个验证入口：让读者能通过一组最小用例观察哪些方法会被 advice 命中、哪些不会。

### 第 34 章：05. exposeProxy（expose proxy）

- 建议解释它解决的本质问题：让“当前线程的代理对象”可被拿到，从而绕开自调用绕过代理的问题。
- 补强实现直觉：说明它通常依赖 ThreadLocal（或等价机制）绑定当前代理/调用上下文，并解释并发与嵌套调用下的注意事项。
- 补强使用边界：什么时候该用、什么时候不该用（例如滥用导致耦合/调试困难/递归风险）。
- 给出一个最小实验：展示开启/不开启 exposeProxy 的行为差异，以及如何验证拿到的是“代理”而不是“目标对象”。

### 第 35 章：06. 调试与排障（debugging）

- 建议补强一个“排障 checklist”：先确认是否代理、再确认代理类型、再确认 Advisors/Interceptors、最后确认 pointcut 是否命中与顺序是否正确。
- 补强“如何在调试器里看懂”：例如如何从 proxy 身上拿到 `Advised` 信息、如何查看 interceptor chain、如何识别当前 advice 是谁。
- 补强“常用日志点位”：给出推荐的日志开关/包名（以不淹没输出为前提），并说明日志能回答什么问题。
- 与 Guide 的断点地图/分支矩阵联动：调试章节应该是这些公共资产的“应用示范”，并引用它们而不是重复列。

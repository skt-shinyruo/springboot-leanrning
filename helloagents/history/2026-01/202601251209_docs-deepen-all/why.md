# Change Proposal: 全量文档加深（面试复习 / 源码级深入）

## Requirement Background

当前仓库的文档体系已经具备“模块化 + 章节化 + 可跑入口（Labs/Exercises）”的基础，但在“源码级深入”的目标下仍存在以下痛点：

1. **深度不均**：部分章节偏概念/用法，缺少“主线调用链 + 关键分支 + 可验证入口”的闭环，导致面试复习与源码定位成本偏高。
2. **可跑入口分散**：仓库已存在大量 `*LabTest/*ExerciseTest`，但章节与测试入口的绑定不够稳定/统一，难以做到“先跑再读/边跑边证”。
3. **排障与边界缺口**：生产排障清单、典型坑位、性能/并发语义（尤其是代理、事务、异步、缓存、MVC 链路）需要更系统的“现象→根因→验证→修复”落地路径。
4. **一致性维护成本高**：全量章节规模较大（文档文件数 1000+），纯人工维护章节结构与导航容易漂移，需要更强的自动化门禁来保证长期可维护。

因此，本变更希望以“全量覆盖 + 一致性契约 + 可运行证据链”为核心，把文档升级为面向**面试复习 / 源码级深入**的可验证教材。

## Product Analysis

### Target Users and Scenarios

- **User Groups：**
  - 面试复习者：需要用最短路径回忆“主线 + 分支 + 常见坑 + 典型题”。
  - 源码级深入者：需要明确的断点入口与可跑证据链，能解释机制“为何如此”。
  - 生产排障者：需要从症状快速回到机制分支，并落到可验证入口。

- **Usage Scenarios：**
  - 面试前 1–2 天：快速扫主线时间线、决策树、坑位与自测题。
  - 阅读源码：从文档给的断点地图入手，沿主线走到关键分支。
  - 线上故障复盘：从“现象/根因/验证/修复”清单做快速定位。

### Value Proposition and Success Metrics

- **Value Proposition：**
  - 每章都具备“可导航 + 可验证 + 可断点 + 可排障”的最小闭环；
  - 对关键模块补齐“主线调用链 + 决策树/对比表 + 性能并发语义 + 生产排障清单”；
  - 让测试（Labs/Exercises）成为文档的证据链，形成可回归的学习资产。

- **Success Metrics：**
  - `docs/**` 下所有章节均包含稳定的尾部入口块（Bookify），且二次运行脚本无重复叠加（幂等）。
  - `docs/**` 下 Markdown 相对链接检查为 0 断链。
  - 22 个模块每个模块至少具备：
    - 目录页（README）可顺读；
    - 主线时间线 + 断点地图可用；
    - 至少 1 个可跑 `*LabTest` 入口，并在文档中可追溯。
  - 核心模块（Beans/AOP/Tx/Web MVC/Security）补齐“生产排障清单 + 性能/并发语义 + 决策树/对比表”并可由 Lab/Test 验证关键结论。

### Humanistic Care

- 避免在文档与测试中引入任何真实 PII/敏感数据样例；
- 示例与排障条目尽量覆盖“新手容易误解”的边界情况，降低学习挫败感；
- Exercises 默认禁用（`@Disabled`）以避免 CI/回归被练习题阻断。

## Change Content

1. 全量章节结构强化：补齐“主线/关键分支/验证入口/断点包/坑位/自检题”。
2. 全量章节可跑入口固化：统一章节与 `*LabTest/*ExerciseTest` 的绑定与导航。
3. 全量排障与边界体系化：将常见坑与生产排障清单模块化沉淀。
4. 自动化门禁：引入/增强脚本，保证全量文档长期一致性与可维护性。

## Impact Scope

- **Modules：**
  - `docs/*` 全部模块（22 个）。
  - `spring-core-modules/*` 与 `spring-boot-modules/*` 的测试入口（Labs/Exercises/Solutions）。
- **Files：**
  - 全量 Markdown 文档（章节结构、导航、入口块、对比/决策树、排障清单等）。
  - `scripts/*` 文档自动化/审计脚本（新增/增强）。
  - `helloagents/wiki/*`（知识库索引与约定同步）。
- **APIs：** 无对外 API 变更。
- **Data：** 无数据模型变更。

## Core Scenarios

### Requirement: 全量章节契约升级
**Module:** docs（全量）

为所有章节补齐“可导航 + 可验证 + 可断点 + 可排障”的最小闭环，确保面试复习与源码级深入都能快速落地。

#### Scenario: 读者需要快速建立本章预期并验证结论
- 章节包含“本章要点/学习卡片/主线提示”
- 章节包含可运行入口（Lab/Test）与断点建议

### Requirement: Labs/Exercises 与文档绑定（全量）
**Module:** tests（全量模块）

把可运行测试作为文档证据链：从“跑起来的现象”回到“机制主线与分支”。

#### Scenario: 读者从文档直接跳到可跑入口
- 文末存在稳定入口块（Bookify）
- 推荐 Lab/Test 可在对应模块下运行并复现关键结论

### Requirement: 排障清单 + 性能/并发语义补齐（全量模块，核心模块优先）
**Module:** docs（全量）

以“现象→根因→验证→修复”组织坑位/排障，并对关键机制补齐性能与并发语义的可验证说明。

#### Scenario: 生产问题复盘需要快速定位机制分支
- 章节/附录包含排障条目与分流
- 提供推荐断点与可跑入口验证结论

## Risk Assessment

- **Risk:** 全量批处理导致链接/导航漂移、内容一致性下降  
  **Mitigation:** 引入自动化检查（相对链接检查、章节契约检查），并以模块为单位分批验收。
- **Risk:** 文档生成/重写脚本对仓库结构假设不一致导致误改  
  **Mitigation:** 在脚本层统一路径解析（复用 `scripts/repo_paths.py`），支持 `--module` 子集 dry-run。
- **Risk:** Labs/Exercises 增加导致测试时间变长或不稳定  
  **Mitigation:** Exercises 默认 `@Disabled`，核心 Lab 断言稳定契约，分模块执行与增量验证。
